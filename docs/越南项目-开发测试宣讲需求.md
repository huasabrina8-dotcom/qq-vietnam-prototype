## 一、需求背景与目标

### 背景

越南业务需要自己的运营后台，值班要查会员、审充提、做资金调整、配游戏和活动。365 管理后台已经有这套菜单和页面。若继续和 Juan365 共用一个仓库、一套 `juan365_admin_v4`，越南的配置和菲律宾站的配置会写在一起，改一边会碰到另一边。

本期先把 365 管理后台整套照搬到独立项目库，菜单和交互保持一致，数据键分开。越南盾面额、本地合规名单等待后续单独开需求，本期不改已照搬的字段。

### 路径 / 权限 / 联通

| 项 | 说明 |
|----|------|
| 前台 | 本期没有越南前台。会员侧不在本仓。 |
| 后台入口 | `admin/index.html#/dashboard`。打开即进，`admin/login.html` 只跳到仪表盘。 |
| 谁能进 | 原型按超级管理员展示全部一级菜单。正式权限仍是超管、客服、财务、运营四类，矩阵与拷贝来的 365 后台一致；原型不校验账号。 |
| 不能进 | 无菜单权限的角色看不到对应子页。原型不接真实鉴权。 |
| 联通 | 同一会员账号、订单号、金额在会员、充提、资金、活动、报表多页复用，只在本仓 `vietnam_admin_v1` 内。不读写 `juan365_admin_v4`，不联通 365 前台、体育、U8、活动平台。 |
| 资金相关 | 系统入款、系统打款、充值审核、提款审核、活动发放沿用 365 后台的二次确认和流水写法。原型只改本地余额。 |

### 目标

1. 宣讲和开发能按本原型走完 365 管理后台已有路径：查会员、审充提、资金调整、开关游戏、配活动、看报表。
2. 越南项目与 365 管理后台分库、分存储键，互不覆盖。
3. 列表有真实感虚拟数据，空列表只在空数据开关下出现。

### 业务要求

- 菜单树锁定为下方一级与子菜单，不得删成瘦侧栏，也不得改成体育、U8 或活动平台的菜单。
- 金额两位小数；时间 `YYYY-MM-DD HH:mm:ss`；手机可脱敏。
- 加款、扣款、审核通过、删除必须二次确认。
- 活动类型、抽奖模版、用户分层配置与拷贝时的 365 后台同一套，禁止第二公式。
- 明确不做：越南前台大厅、把本仓改动回写 365、把抽奖定稿自动同步进本仓、把 NDRP 等已照搬页面改写成越南监管口径（另开需求）。

### 2.1 壳层

| 项 | 内容 |
|----|------|
| **功能名称** | 后台壳层 |
| **功能说明** | 暗色侧栏 + 顶栏 + 内容区 + 抽屉 + 二次确认。结构与 365 管理后台相同。 |
| **展示规则** | 侧栏 Logo 文案为 `JUAN`，点击进入 `#/dashboard`。浏览器标题为「越南管理后台」。顶栏左侧为当前页标题和折叠；右侧为搜索、全屏、通知、设置、管理员头像。当前菜单组展开，当前子项高亮。 |
| **交互逻辑** | 点一级菜单展开或收起。点子菜单改 hash 并打开页签。点 Logo 回仪表盘。头像展开后点退出，留在后台。搜索、通知、设置出对应提示。全屏调用浏览器全屏。 |
| **业务规则** | 无权限的子菜单不渲染。存储只写 `vietnam_admin_v1`。 |
| **状态说明** | 默认落在仪表盘，会员管理组展开。无匹配 hash 回仪表盘。侧栏可折叠。 |
| **延伸** | 正式环境退出回到登录页。本期登录页只做跳转。 |

## 三、流程图 / 交互说明

```text
打开 / 
  → 进入后台 #/dashboard
  → 点侧栏一级菜单（展开）
  → 点子菜单（改 hash，开页签）
       → 查询 / 重置 / 翻页
       → 新增或编辑：开抽屉 → 确定保存 / 取消关闭
       → 资金或审核：二次确认 → 确定后改本仓余额或状态并记流水
       → 点 Logo 或仪表盘页签回到 #/dashboard
```

分支：

- 无匹配 hash：回到仪表盘。
- 确认框点取消：不改数据，留在当前页。
- 抽屉点关闭或取消：不保存，回到列表。
- 退出登录：提示后仍留在后台。

## 六、风险预估

### 6.1 和 365 后台串数据

- **是什么**：两个后台若共用 `juan365_admin_v4`，越南改活动或余额会覆盖 Juan365 原型数据。
- **影响**：宣讲对不上；若有人把原型键当成正式配置，会把错误活动或余额带到另一站点。资金口径被串改。
- **出问题后怎么处理**：立刻改回独立键，清掉本仓对 `juan365_*` 的读写，用本仓虚拟数据重新打开核对。
- **有没有降级**：有。分仓库、分键后，即使页面长得一样，浏览器里的数据也不互通。

### 6.2 照搬后被当成越南已本地化

- **是什么**：NDRP、综合报告税率、Logo「JUAN」、抽奖里的原分享账号仍是 365 后台原文。货币列表里虽有 VND，全站金额没有改成只按越南盾结算。
- **影响**：按越南监管或越南盾面额上线会判错名单、算错税、发错活动门槛。
- **出问题后怎么处理**：本期宣讲标明「界面照搬，本地化未做」。上线前单开越南合规和币种需求，未改完不得当生产口径。
- **有没有降级**：有。继续用本原型做菜单和流程宣讲，不合规字段不上生产。

### 6.3 资金操作重复入账

- **是什么**：审核通过或系统入款被重复确认。
- **影响**：余额多加，活动或彩金重复发放。
- **出问题后怎么处理**：同一单只允许成功一次；重复请求不写第二笔流水。发现多笔时按流水冲正，并记下操作日志。
- **有没有降级**：有。确认框取消即中止；正式环境用单号幂等，超时不自动重试入账。

### 6.4 抽奖或活动被改成第二套规则

- **是什么**：本仓活动抽屉被单独改一版，和 365、抽奖仓的分享开关、下雨表、保底不一致。
- **影响**：同一活动在越南和 365 发奖结果不同，测试无法验收。
- **出问题后怎么处理**：以拷贝时的模版为准回退本仓活动段。若要改规则，先改抽奖需求仓，用户点名越南后再同步。
- **有没有降级**：有。未点名越南时，本仓保持照搬版本继续宣讲。

### 6.5 改动回写 365 或被定稿同步覆盖

- **是什么**：把越南页面拷回 `qq-admin-prototype`，或抽奖定稿时把 Juan365 抽奖模版写进本仓。
- **影响**：365 菜单被越南需求改掉，或越南正在对的页面被另一套定稿覆盖，线上配置来源混乱。
- **出问题后怎么处理**：停止拷贝，按各自仓库回退。365 只接受用户对 365 说的定稿；越南只接受用户点名越南的改动。
- **有没有降级**：有。两边仓库和存储键隔离，日常改动不 push。
